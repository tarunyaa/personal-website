Mapping Out the Future of Chip Design

* purely speculative

Chip design is a loop, not a flow

When I was preparing for my NVIDIA interviews, I memorized the ASIC design flow.

Architecture. Microarchitecture. RTL. Verification. Synthesis. Floorplanning. Place and route. Tapeout.

The diagram is misleading, though. Chip design doesn’t flow linearly from step one to eight. It’s a highly iterative process. In fact, chip design is more like a collection of nested loops.

Two properties of chip design make these loops unavoidable:

  1. The combinatorial complexity of a multi-objective optimization problem
  2. Asymmetric information about constraints and objectives caused by technology-node and market changes

Chip design is heavily abstracted

Humans make chip design tractable by dividing it into stages, as seen in the ASIC design flow. Organizations are built around these stages because no one person can reason about the entire chip at once.

Conway’s law suggests that products tend to mirror the organizations that produce them. As a result, today’s chips are highly hierarchical and optimized against fixed bandwidth and latency contracts.

AI removes the need for abstractions built for human comprehension. It can instead operate over representations designed for machine search.

Jalapeño offers an early example of one agentic kernel-optimization loop. OpenAI describes AI optimizing how work is mapped, placed, scheduled, and coordinated; Zartbot makes the loop concrete: generate a kernel candidate, run it on a simulator or silicon, then revise placement, pipelining, prefetching, and communication. Zartbot documents a 40-hour DeepSeek MLA optimization run, and OpenAI reports that selected Codex-generated GPT-OSS implementations ran 1.5–1.8× faster than expert-written versions.

The first step will be bounded loops

The near-term version of the future is much less dramatic than an autonomous agent producing a complete chip.

I believe it looks like engineers identifying bounded parts of the flow where three things exist:

  1. A design can be modified automatically
  2. There is a reliable reward function for evaluation
  3. Evaluation is fast enough to support repeated iteration

An agent could propose a change, run the relevant tools, inspect the result, and revise its proposal. This is the recursive loop where the agent uses its reasoning to iteratively prune a combinatorially complex search space.

This matters because today’s chips are partly limited by how many useful iterations can be completed before tapeout. If an agent can run 10× more iterations and experiments overnight, engineers can search a larger design space.

The real bottleneck is evaluation

Any search procedure needs feedback about which candidates are promising. The reward function needs to be both fast and trustworthy.

The issue with physical design is that conventional EDA flows can be slow. So, we either need better tools or proxy rewards: intermediate estimates of timing, power, congestion, and other constraints that can guide search. However, these proxies need to be representative of the final objective, which is tricky.

Before search comes representation

Evaluation alone isn’t enough. The agent must understand what it’s searching for.

Since chip design is distributed across stages of the ASIC design flow, each stage has its own vocabulary or ontology. What’s lacking is a unified, machine-usable representation that connects product-level goals to microarchitecture, RTL, physical implementation, and verification. This makes it difficult to run loops across stages.

In the short run, as a result, a lot of the work to enable AI in chip design will look unglamorous: documenting flows, constructing ontologies, and defining constraints.

The future

Initially, agents will probably accelerate individual stages while preserving the existing ASIC flow. However, once the ontologies are built, there is a possibility that we can cross the boundaries and connect the loops.

An agent changes a microarchitectural choice, observes its effect after synthesis and physical design, then uses that information to revise the architecture. A placement decision feeds back into the network topology. A memory-system decision is evaluated not only through an abstract model, but through its downstream effects on area, wiring, and energy.

Search could then operate across boundaries that humans currently find it hard to cross. This enables the agent to learn policies for pruning the search space and discovering better chips.

The future of chip design might be a loop that enables shorter tapeouts and better chips.
