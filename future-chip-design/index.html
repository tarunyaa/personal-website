Mapping Out the Future of Chip Design

* purely speculative

Chip design is a loop, not a flow

When I was preparing for my NVIDIA interviews, I memorized the ASIC design flow.

Architecture. Microarchitecture. RTL. Verification. Synthesis. Floorplanning. Place and route. Tapeout.

The diagram is misleading, though. Chip design doesn’t flow linearly from stage one to eight. It’s a highly iterative process. In fact, chip design is more like a collection of nested loops.

Two properties of chip design make these loops unavoidable:

  1. The combinatorial complexity of a multi-objective optimization problem
  2. Asymmetric information about constraints and objectives caused by technology-node and market changes

Chip design is heavily abstracted

Humans make chip design tractable by dividing it into stages. Organizations are built around these stages because no one person can reason about the entire chip at once.

Conway’s law suggests that products tend to mirror the organizations that produce them. As a result, today’s chips are highly hierarchical and optimized against fixed bandwidth and latency contracts.

AI removes the need for abstractions made for human comprehension.

Jalapeño offers an early example. According to Zartbot’s reconstruction, it replaces CUDA’s runtime CTA-to-SM assignment with compile-time spatial mapping. This exposes physical core placement, HBM-slice affinity, tiling, pipelining, and prefetch distance to AI-guided search. OpenAI confirms the broader direction: local tensors, explicit communication, and predictable synchronization, with AI optimizing mapping, placement, scheduling, and coordination.

The abstraction has not disappeared. It has moved from dynamic hardware scheduling to explicit compile-time spatial mapping. Zartbot reports a 40-hour DeepSeek MLA optimization trajectory across precision, rescaling, matmul scheduling, prefetching, and memory access. Because parts of the compiler pipeline are inferred, this is evidence of AI searching implementation decisions, not official confirmation that one agent searched every variable continuously for 40 hours.

The first step will be bounded loops

The near-term version of the future is much less dramatic than an autonomous agent producing a complete chip.

I think it starts with engineers identifying bounded parts along the ASIC design flow where three things are true:

  1. The system can make valid design changes automatically
  2. The quality of those changes can be evaluated reliably
  3. Evaluation is cheap and fast enough to repeat many times

When those conditions hold, an agent can close the loop: propose → evaluate → diagnose → revise. Using reasoning and feedback from previous attempts, it prunes the search space at test time, much like a human engineer.

This matters because today’s chips are partly constrained by how many useful iterations engineers can complete before tapeout. Automating some of those loops could let engineers explore more alternatives within the same design schedule.

A bottleneck is evaluation

Closing the loop is easy conceptually. Getting useful feedback can be hard. Any search procedure needs fast, trustworthy evidence about which candidates are promising.

Conventional EDA flows can be slow. Faster tools or proxy metrics, such as intermediate estimates of timing, power, and congestion, could guide search. However, those proxies need to represent the final objective accurately, which is tricky.

Before cross-stage search comes representation

Fast evaluation can close a loop between two stages. Connecting loops across stages requires something else: the agent needs to understand how a decision in one representation propagates into another.

Each stage of the ASIC design flow has its own vocabulary and representation. What’s lacking is not necessarily one universal ontology, but machine-usable connections between product goals, microarchitecture, RTL, physical implementation, and verification.

In the short run, much of the work to enable AI in chip design will look unglamorous: documenting flows, structuring tool outputs, mapping dependencies, and defining constraints.

The future

Initially, agents will probably accelerate individual stages while preserving the existing ASIC flow. As the connections between representations improve, those bounded loops can begin to interact.

Suppose an agent changes a cache because an architectural model predicts better performance. After synthesis and physical design, that same choice might increase wire length, congestion, or timing pressure. The agent could feed those downstream effects back into the architectural decision and reject a choice that only looked good in a silo.

Search could then operate across boundaries that humans currently find it hard to cross. This enables the agent to learn policies for pruning the search space and discovering better chips.

If AI lowers the cost of crossing boundaries, which boundaries in today’s ASIC flow still need to exist?
